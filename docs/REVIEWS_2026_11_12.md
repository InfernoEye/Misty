# Review: direct visual readiness and server launch, 2026-11-12

## Scope

This review covers the direct-action screen-summary path in
`app/brain/direct_actions.py` and the shared `llama-server` launch tuned in
`app/brain/agent.py`. It does not certify the whole repository.

Direct screen summaries now own VLM readiness instead of relying on a voice
preload that transcription may already have released, so a page summary starts
the active-window model before the first capture. Routing was also fixed: a
page noun wins over the whole-screen fallback, so "summarize what I'm seeing on
this page" targets the active window while a bare "summarize what I'm seeing"
still falls through to the primary screen. A leading search connector
("Search for X" / "Szukaj dla X") is stripped once before the topic is read, so
a topic that begins with the same word ("For King and Country") survives. The
shared server's output budget was raised to 16384 tokens (`-n`) with
`--cache-type-k/-v q4_0`, `--flash-attn on` and `--load-mode none`, keeping a
page summary, a plan, or a long research answer inside one 32768-token context
window.

The baseline command ran 2,594 tests, OK, six skipped (five new tests above the
previous baseline for this change set).

## Findings and corrections

| Priority | Finding | Location | Correction |
| --- | --- | --- | --- |
| P1 | A screen summary was produced by both the caller and the routing regex, doubling the VLM call and crashing on the oversized result. | `app/brain/direct_actions.py`, `resolve_direct_action` | Re-order so the page-noun route wins over the whole-screen fallback, and guard it so the summary runs once. |
| P2 | The search connector "Search for"/"Szukaj dla" leaked into the topic and biased routing. | `app/brain/direct_actions.py`, `_clean_query` | Strip one leading `for`/`dla` connector before the query; a topic that starts with the same word survives. |
| P2 | Direct screen summaries assumed a voice preload had already started the shared VLM server. | `app/brain/agent.py`, `_execute_direct_action` | Call `ensure_reasoning_ready()` on the inspect-screen path and check cancellation before the capture. |
| P2 | The 8192-token output budget could overflow a single 32768-token context window for long plans or research answers. | `app/brain/agent.py`, `_server_command` | Raise `-n` to 16384 and add `--cache-type-k/-v q4_0`, `--flash-attn on`, `--load-mode none`. |

## Boundaries retained

- A page summary still requires approval and the usual cancellation ownership;
  starting the model directly does not bypass the policy gate.
- Direct summaries bypass the planner's JSON plan but keep the OCR fallback, the
  page-read requirement, and the egress fence for anything private.
- The new server flags are launch tuning only. They do not change model inputs,
  approval gates, or the audit trail.

## Validation

- Full suite: `.venv/bin/python -m unittest discover -s tests` ran 2,594 tests,
  OK, six skipped. Five new direct-readiness tests in
  `tests/test_direct_visual_readiness.py` cover start-before-capture, start
  failure, cancellation, OCR-only, and the navigation paths.
- Python compile: `.venv/bin/python -m compileall -q app tests` passed;
  `git diff --check` passed.
- No test asserts on the `-n` value or the new server flags, so the tuning is
  checked against the installed `llama-server --help`, not live inference.
  The real-server integration test stays skipped until a server runs on
  `BASE_URL`; a live page summary, a long research answer, and a physical
  Escape press still need a controlled user check after rebuilding the helper
  and restarting Misty.

# Review: cancellation and public research, 2026-11-12

## Scope

This review covers the request lifecycle changed in commit `4cef236`, public
research routing/retrieval/reporting, the shortcut command reader, approval
admission, and process-session ownership tests. It does not certify the whole
repository or the historical snapshots. Review passes traced execution and
integration, resource ownership and privacy boundaries, then validation,
failure handling, and test assumptions.

The baseline command `.venv/bin/python -m unittest discover -s tests` ran 2,570
tests with one failure, one error, and six skips. Both failing cases came from
process-session assumptions in the test environment.

## Findings and corrections

| Priority | Finding | Location | Correction |
| --- | --- | --- | --- |
| P1 | A topical headline excluded lower-ranked sources even if the topical page could not be read. | `app/brain/tools.py`, `web_research` dispatcher | Keep stable relevance ranking and try distinct candidates within the existing fetch budget. |
| P2 | The excerpt fallback restored cookie/subscribe lines after the filter rejected them, allowing a long consent notice to count as readable evidence. | `app/brain/tools.py`, `_readable_excerpt` | Retain only non-boilerplate short lines in the fallback; cover consent-only pages and short specification rows. |
| P2 | Fetch failures shared one count, hiding whether a URL was blocked, an HTTP request failed, or a page lacked readable text. | `app/brain/tools.py`, research result diagnostics | Add fixed-category counts and distinct no-results/no-readable-sources codes; omit raw errors and failing URLs. |
| P2 | A blocked destination step appeared as a planned lookup and triggered a listing-match caveat despite no lookup. The response repeated action counts. | `app/brain/agent.py`, final research response | Report actual attempted destination state and provide a concise no-evidence failure. Keep the detailed execution report in activity/audit events. |
| P1 | Cancellation could happen just before a new confirmation entered the broker. | `app/engine/voice_controller.py`, confirmation admission/decision | Check the current owner's cancellation state across admission and resolution. |
| P1 | A prompt could resolve while the audio device opened, before the controller published confirmation-recording ownership. | `app/engine/voice_controller.py`, spoken confirmation startup | Serialize recording ownership and check the exact pending request after device startup; discard orphan audio. |
| P1 | An agent-factory exception before the session cleanup block could leave request admission busy. | `app/engine/voice_controller.py`, session startup | Reset failed admission and preserve cleanup ownership. |
| P2 | Process-session tests assumed the runner had a positive session ID; the sandbox exposed zero. | `tests/test_launch_focus_gate.py`, `app/desktop/launch_window.py` | Use deterministic positive-session fixtures and test rejection of zero, invalid IDs, and invalid PIDs. Keep unknown ownership fail-closed. |

## Boundaries retained

- Research uses the public-address fetcher with the existing timeout, byte,
  content, and redirect limits. It does not bypass a site refusal or replay a
  refused URL through another backend.
- A readable excerpt remains a requirement for successful `web_research`.
  Search snippets do not establish a recommendation or verified listing.
- Source-present candidate names prove literal presence, not suitability,
  price, seller quality, or availability. Answers must state evidence gaps.
- Cancellation prevents future work; it does not undo delivered input or
  forcibly stop an uninterruptible model/IO operation.
- The tests leave live shortcut integration opt-in. No desktop input, model
  inference, live network probe, or application restart formed part of this review.

## Validation

- Final full suite: `.venv/bin/python -m unittest discover -s tests` ran
  **2,589 tests, OK, six skipped**. The parent reran the suite after reviewing
  the fixes; the child lifecycle review reached the same result.
- Research/fetch-focused checks: **129 tests passed**.
- Lifecycle-focused checks: **92 tests passed, one skipped**.
- Python parse/import compilation: `.venv/bin/python -m compileall -q app tests`
  passed. `git diff --check` passed.
- Helper: CMake configure/build passed; offline CTest passed **1/1**. The pipe
  regression does not start the KDE shortcut helper.
- The suite still emits temporary-directory `ResourceWarning` messages. They
  did not fail this run; this review did not remove existing fixture warnings.

### Follow-up outside this fix set

The broader model cleanup path uses bounded joins. If a preload outlives that
join, existing cleanup can clear model references while its loader remains
alive. The cancelled-recording path waits for its preload owner, but this review
did not redesign model arbitration across all cleanup paths. A separate ownership
review should cover timed-out loaders before making a wider concurrency claim.

The user's failed research log predates these fixes and does not identify its
individual HTTP/fetch errors. The review found a candidate-selection bug but
cannot prove that bug caused the user's particular failure. Live SearXNG/model
research and a physical Escape press still need a controlled user check after
rebuilding the helper and restarting Misty.
