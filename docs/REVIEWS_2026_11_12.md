# Review: cancellation and public research, 2026-11-12

## Scope

This review covers the request lifecycle changed in commit `4cef236`, public
research routing/retrieval/reporting, the shortcut command reader, approval
admission, and process-session ownership tests. It does not certify the whole
repository or the historical snapshots. Review passes traced execution and
integration, resource ownership and privacy boundaries, then validation,
failure handling, and test assumptions.

The baseline command `.venv/bin/python -m unittest discover -s tests` ran 2,570
tests with one failure, one error, and six skips. Both failing cases came from
process-session assumptions in the test environment.

## Boundaries retained

- Research uses the public-address fetcher with the existing timeout, byte,
  content, and redirect limits. It does not bypass a site refusal or replay a
  refused URL through another backend.
- A readable excerpt remains a requirement for successful `web_research`.
  Search snippets do not establish a recommendation or verified listing.
- Source-present candidate names prove literal presence, not suitability,
  price, seller quality, or availability. Answers must state evidence gaps.
- Cancellation prevents future work; it does not undo delivered input or
  forcibly stop an uninterruptible model/IO operation.
- The tests leave live shortcut integration opt-in. No desktop input, model
  inference, live network probe, or application restart formed part of this review.

### Follow-up outside this fix set

The broader model cleanup path uses bounded joins. If a preload outlives that
join, existing cleanup can clear model references while its loader remains
alive. The cancelled-recording path waits for its preload owner, but this review
did not redesign model arbitration across all cleanup paths. A separate ownership
review should cover timed-out loaders before making a wider concurrency claim.

The user's failed research log predates these fixes and does not identify its
individual HTTP/fetch errors. The review found a candidate-selection bug but
cannot prove that bug caused the user's particular failure. Live SearXNG/model
research and a physical Escape press still need a controlled user check after
rebuilding the helper and restarting Misty.
